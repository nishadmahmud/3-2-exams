**(b) How the phases of a compiler can be grouped? How does the Lexical Analyzer increase the efficiency of the compiler?** [2+2]
> **Answer:**
> The phases can be grouped into two main parts:
> 1. **Frontend (Analysis):** Includes Lexical Analysis, Syntax Analysis, Semantic Analysis, and Intermediate Code Generation. It depends only on the source language.
> 2. **Backend (Synthesis):** Includes Code Optimization and Target Code Generation. It depends on the target machine architecture.
> 
> The Lexical Analyzer increases efficiency by:
> * Stripping out whitespace, tabs, and comments, saving the parser from handling meaningless characters.
> * Converting a long stream of characters into a significantly shorter, structured sequence of tokens, speeding up parsing and reducing memory overhead.
>

**2. (a) What is the purpose of assembler, linker and loader in compiler?** [3]
> **Answer:**
> *   **Assembler:** Translates the target assembly code produced by the compiler into relocatable machine code.
> *   **Linker:** Resolves external memory addresses and links the relocatable machine code with other object files and library files to produce a single executable.
> *   **Loader:** Loads the final executable machine code into the computer's memory (RAM) for execution.

**4. (a) Show that all binary strings generated by the following grammar have values divisible by 3.** [2]<br>
*Hint. Use induction on the number of nodes in a parse tree.*<br>
$num \rightarrow 11 \mid 1001 \mid num\ 0 \mid num\ num$
> **Answer:**
> **Base Cases (Leaves):**
> *   $11$ in binary is $3$, which is divisible by 3.
> *   $1001$ in binary is $9$, which is divisible by 3.
> 
> **Inductive Step (Internal Nodes):**
> Assume any $num$ generated so far is divisible by 3 (i.e., $num = 3k$).
> *   For $num \rightarrow num\ 0$: Appending a 0 in binary multiplies the value by 2. The new value is $2 \times 3k = 6k$, which is divisible by 3.
> *   For $num \rightarrow num_1\ num_2$: Let $num_2$ have $L$ bits. Appending $num_2$ to $num_1$ is equivalent to $num_1 \times 2^L + num_2$. Since both are divisible by 3, $(3k_1 \times 2^L) + 3k_2 = 3(k_1 2^L + k_2)$, which is divisible by 3.
> 
> By mathematical induction on the parse tree nodes, all generated strings represent values divisible by 3.

**5. (a) We can prove that two regular expressions are equivalent by showing that their minimum-state DFA's are the same, except for state names. Using this technique, show that the following regular expressions are all equivalent.** [3]<br>
i. $(a \mid b)^*$<br>
ii. $(a^* \mid b^*)^*$<br>
iii. $((\epsilon \mid a)b^*)^*$
> **Answer:**
> *   **i. $(a \mid b)^*$**: Represents all possible strings over $\{a,b\}$, including $\epsilon$. Its minimal DFA has exactly 1 state (an accepting state) with loops on `a` and `b`.
> *   **ii. $(a^* \mid b^*)^*$**: The inner expression produces any pure string of `a`s or pure string of `b`s. The outer Kleene star allows arbitrary concatenation of these pure strings, meaning we can alternate `a`s and `b`s freely to form *any* sequence. Its minimal DFA is identical to (i).
> *   **iii. $((\epsilon \mid a)b^*)^*$**: The inner part produces an optional `a`, followed by any number of `b`s. By repeating this pattern with the outer star, we can insert any number of `a`s separated by any number of `b`s, effectively generating any string over $\{a,b\}$. Its minimal DFA is also identical to (i).
> 
> Since all three expressions reduce to the same minimal 1-state DFA accepting $(a \mid b)^*$, they are strictly equivalent.

**(b) Try to design grammar for each of the following languages. Which languages are regular?** [2]<br>
i. Strings of 0's and 1's with an equal number of 0's and 1's.<br>
ii. Strings of 0's and 1's with an unequal number of 0's and 1's.<br>
iii. Strings of 0's and 1's of the form xy where $x \neq y$.<br>
iv. Strings of 0's and 1's of the form xx.
> **Answer:**

> *   **iv. $xx$:** This language is **Not Context-Free** (requires a Context-Sensitive Grammar). (**Not Regular**)
> 
> **None** of the above languages are regular because they all require counting or matching characters, which a Finite Automaton cannot do (violates Pumping Lemma).

**7. a) What is Three Address Code? Explain the concepts to build Three Address Code.** [2]
> **Answer:**
> **Three Address Code (TAC)** is a generalized intermediate representation where each instruction has at most three operands (typically two sources and one destination).
> **Concepts to build it:** It is built by breaking down complex, nested expressions into a sequence of simple atomic operations (like `x = y op z`). It linearizes the syntax tree by introducing temporary variables (e.g., `t1`, `t2`) to hold the intermediate results of each sub-expression.

**b) Define Quadruples, Triples and Indirect Triples.** [3]
> **Answer:**
> *   **Quadruples:** A data structure for TAC consisting of 4 fields: `op` (operator), `arg1` (first operand), `arg2` (second operand), and `result` (destination). It explicitly names temporary variables.
> *   **Triples:** A data structure with only 3 fields: `op`, `arg1`, and `arg2`. It avoids creating temporary variables by referring directly to the *index* (or position) of the statement that computed the value.
> *   **Indirect Triples:** An extension of Triples that uses a separate array of pointers to the triples. This makes optimization easier; instructions can be reordered by moving pointers without invalidating the indices used in the triples themselves.

> 
> **i. `x= f(a) + f(a) + f(a)`**

>

> `t2 = call g(b, c)`
> `x = t1 / t2`
>

> 
> **iv. `x=++f(a)`**
